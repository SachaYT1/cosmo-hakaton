# Прогресс — Мониторинг природных пожаров (КосмоХакатон 2026)

Статус на 2026-09-18. Обновляется по ходу работы.

## Что сделано

### 1. Разбор постановки и данных
- Прочитаны обе PDF-постановки (кейс + критерии оценки) и вся сопутствующая
  документация (`fire-aoi/README.md`, `.geojson/.prj/.cpg`).
- Распаковано и изучено содержимое `fire-train-renamed.tar` (2.3 ГБ) —
  вытащена реальная структура файлов на диск (важно: изначальные
  предположения по именам папок были неверны, поправлены после факт-чека):

  ```
  train/af/{viirs,aux,masks}/{chip_id}_*.tif  + meta.csv   (420 чипов)
  train/bs/{sentinel1_pre,sentinel1_post,sentinel2_pre,sentinel2_post,aux,masks}/{chip_id}_*.tif + meta.csv  (224 чипа)
  ```
- Извлечены и прочитаны оба `meta.csv` (структура колонок, примеры значений).

### 2. Архитектура репозитория (скелет)
Полная структура каталогов и точки входа под требования постановки
(`python inference.py --data-dir ... --output ...`, `train.py`, Docker,
FastAPI-сервис, метрика) — см. `README.md` за деталями дерева.

### 3. Модели
- **AF (`src/fireapp/af/model.py`)** — `UNetSmall`: лёгкий U-Net на 3 уровня
  (base=32), вход 13 каналов (VIIRS I1-I5 + 8 aux-слоёв), выход — логиты
  бинарной маски горения. Осознанно неглубокий — 420 train-чипов не тянут
  тяжёлую сеть, а ImageNet-претрейн бесполезен (входы не RGB).
- **BS (`src/fireapp/bs/model.py`)** — `UNetSiamese`: общий энкодер
  применяется к pre/post отдельно (одни веса), признаки фьюзятся как
  `[pre, post, |pre-post|]` на каждом уровне; статические слои (DEM, уклон,
  экспозиция, покров) подмешиваются в bottleneck. Выход — логиты на 4 класса
  (0 не горело, 1/2/3 степени поражения).

### 4. Датасеты
- **`af/dataset.py`** — читает `viirs`+`aux`, нормализует (I4/I5 центрируются
  вокруг фона ~300K вместо [0,1] — иначе теряется главный признак горения),
  синхронные flip/rot90-аугментации x+маски.
- **`bs/dataset.py`** — собирает ветки `pre`/`post` (S2 отражение [0,1] + S1 в
  дБ + NBR, посчитанный из B8A/B12 этой же даты), `static` (AUX), достаёт
  валидность из **SCL** (облака/тени/насыщение) и пересекает `valid_pre & valid_post`.
  Нашёл и исправил баг: `valid_mask` изначально не проходила через
  аугментации синхронно с данными — расходилась при flip/rotate.

### 5. Обучение
- **`common/losses.py`** — `AFLoss` (Focal+Dice, под 0.035% позитивных
  пикселей), `BSLoss` (weighted CrossEntropy + multiclass Dice).
- **`common/splits.py`** — групповой train/val split (группы, не строки, не
  утекают между train/val).
- **Найден и исправлен баг в конфиге**: `af.yaml` был настроен на
  `split_by: fire_event_id`, но это поле **пустое для всех AF-строк**
  (заполнено только для BS) — а чипы с одинаковой гео-плиткой (`x_min,y_min`)
  повторяются на разные даты. Реальная утечка локации между train/val.
  Исправлено: AF группируется по `(x_min, y_min)`, BS — по `fire_event_id`.
- **`af/train.py` / `bs/train.py`** — полный цикл обучения с сохранением
  лучших весов по val-лоссу.

### 6. Инференс и метрика
- **`af/infer.py` / `bs/infer.py`** — загрузка весов → forward → пороги/argmax
  → `{chip_id: mask}`.
- **Важное архитектурное решение**: фильтрация техногенных термоаномалий по
  геопространственной повторяемости (`af/postprocess.py`) **не вызывается на
  инференсе** — геопривязка и даты тестовых чипов скрыты организаторами
  намеренно, сопоставить с историческим архивом по координатам нельзя.
  Модель должна научиться отделять факелы от природного горения по
  признакам самого чипа во время обучения; `postprocess.py` — инструмент
  подготовки обучающих данных, а не шаг инференса.
- **`metric/score.py`** — полная реализация официальной метрики:
  `Score = 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev`, микро-усреднение
  TP/FP/FN по всем чипам, проверка совпадения набора `(chip_id, class_id)`.
- **`scripts/build_gt_csv.py`** — собирает `gt.csv` из train-масок в формате
  submission.csv, чтобы гонять `score.py` локально до сдачи.

## Известные ограничения на данный момент

- **На машине нет рабочего Python** (только Windows Store stub-заглушка) —
  ничего из кода фактически не запускалось и не факт-чекалось выполнением.
  Вся проверка до сих пор — чтение кода и ручная сверка логики (например,
  RLE-кодек вручную проверен на примере из Рисунка 8 постановки).
- Веса моделей не существуют — обучение не запускалось.
- Информационно-аналитический сервис (`src/fireapp/service/`) — только
  каркас: роутеры `/api/hotspots`, `/api/burns`, `/api/report` объявлены, но
  реализация (SQL-запросы к PostGIS, векторизация масок) — `NotImplementedError`.
- Фронт (`static/index.html`, `map.js`) — минимальный скелет без реального
  рисования AOI, вызовов API и легенды.
- `af/postprocess.py::filter_persistent_sources` — не реализован (и, как
  выяснилось, не нужен на инференсе; возможно, вообще не нужен, если модель
  учится на исторических признаках напрямую).
